# 灵犀智眸 LingXi Vision

**基于 RT-Thread 与 RA8P1 边缘 AI 的学生课堂行为智能监测系统**

> 2026 RT-Thread 嵌入式大赛参赛作品 ｜ 画面不出教室，只输出数字

---

## 一、项目简介

课堂纪律与听课状态长期依赖教师人工观察，缺少客观、可量化的手段。
「灵犀智眸」基于 **RT-Thread 实时操作系统**与**瑞萨 RA8P1
（Cortex-M85 + Ethos-U55 NPU）**异构算力，在教室边缘侧完成多人人体
姿态估计与课堂行为理解：

- 端侧 NPU 运行 **LingXi-Pose-Tiny**（INT8 量化，课堂场景微调蒸馏版），
  单帧同时检测**最多 10 人**，输出每人 **17 个 COCO 关键点**；
- **课堂行为规则引擎**：判定举手发言 / 低头趴桌 / 站立 / 坐姿端正四类行为；
- **行为事件引擎**：时间防抖 + 边沿触发，把逐帧抖动收敛为结构化教学事件；
- **课堂专注度评分**：行为加权 + 指数滑动平均，输出 0~100 量化指标；
- **教学数据沉淀**：事件带时间戳写入 SD 卡 CSV，支持课后回溯分析；
- **三色 LED 状态指示**：心跳 / 趴桌告警 / 举手提示，本地即时反馈。

全部推理在端侧完成，原始画面不上传、不落盘，对外只输出结构化行为事件。

## 四、系统架构

```
┌──────────────────────────────────────────────────────────┐
│  应用层   行为判定 / 事件引擎 / 专注度评分 / 教学日志      │
├──────────────────────────────────────────────────────────┤
│  AI 层    LingXi-Pose-Tiny INT8  →  Ethos-U55 NPU 驱动    │
├──────────────────────────────────────────────────────────┤
│  RT-Thread 5.x                                            │
│  线程调度 / IPC / 设备驱动框架 / DFS(elm-FAT) / FinSH      │
├──────────────────────────────────────────────────────────┤
│  硬件层   MIPI CSI · RGB LCD · SDIO · USB CDC · GPIO LED   │
└──────────────────────────────────────────────────────────┘
```

### RT-Thread 线程规划

| 线程 | 优先级 | 职责 | 依据 |
| --- | --- | --- | --- |
| t-shell | 20 | FinSH 交互 | 观测优先，避免系统卡死时无法介入 |
| t-monitor | 12 | 帧同步与状态上报 | 中等，保证周期稳定 |
| t-infer | 10 | NPU 推理 | 高，计算密集，需及时拿到时间片 |
| t-capture | 8 | 图像采集 | 最高，采集丢帧会直接拉低全链路 |
| t-rule | 14 | 行为判定与评分 | 较低，微秒级开销 |
| t-log | 22 | CSV 落盘 | 最低，允许被抢占 |

### IPC 分工

| 机制 | 用途 | 超时策略 |
| --- | --- | --- |
| 信号量 | 帧就绪同步（采集 → 推理） | 2 帧周期，超时丢弃并计数 |
| 消息队列 | 检测结果传递 | 满则丢弃最旧，保证实时性 |
| 互斥量 | 共享状态（专注度、峰值） | 持有时间 < 100 μs |
| 事件集 | 告警状态广播 | 无阻塞 |

> 早期版本采用无限等待，实测在 SD 卡接触不良时日志线程阻塞会沿调用链
> 扩散，导致整条流水线停摆。改为超时重试后，单点故障不再扩散。

## 五、行为判定

不使用分类器，用关键点几何关系判定；阈值以躯干长归一化，因此对远近
尺度不敏感：

| 行为 | 判定条件 |
| --- | --- |
| 举手发言 | 手腕高于肩线 0.15 × 躯干长 |
| 趴桌/低头 | 头部低于肩线 0.45 × 躯干长 |
| 站立 | 框高 > 0.55 × 画面高 且 髋踝展开 > 0.18 × 画面高 |
| 坐姿端正 | 以上均不满足 |
| 未知 | 双肩关键点不可见 |

初期尝试过端到端的"课堂行为分类器"，自建标注样本训练四分类头，实测
效果不佳：趴桌与低头在部分视角下特征高度重合，举手与伸展难以区分，
且样本采集成本远超预期。改用几何规则后换教室无需重新采集数据，
单帧判定耗时为微秒级。

### 事件引擎

逐帧计数会产生大量重复事件（一次举手被记成几十次发言），事件引擎把
持续姿态压缩成语义事件：

| 参数 | 取值 | 作用 |
| --- | --- | --- |
| RAISE_CONFIRM | 400 ms | 持续举手才计一次发言 |
| RAISE_RELEASE | 1000 ms | 放下后冷却，避免临界抖动重复计数 |
| DOWN_ALERT | 2000 ms | 持续趴桌才告警 |
| DOWN_RELEASE | 1500 ms | 恢复后滞回解除 |

### 专注度评分

```
focus = EMA( 100 × Σ(行为权重 × 人数) / 总人数 , α = 0.15 )
权重：举手 1.0 · 坐姿 1.0 · 站立 0.85 · 趴桌 0.0 · 未知 0.5
```

## 七、快速开始

```bash
# 1. 跑单元测试（无需硬件）
python -m unittest discover -s tests -p "test_*.py"

# 2. 构建发布目录（含语法校验与双版本一致性校验）
python tools/build_release.py --out dist/sdcard

# 3. 把 dist/sdcard 内容复制到 FAT32 SD 卡根目录，插板、按 RST

# 4. 采集与分析
python tools/serial_monitor.py --port COM7 --save capture/
python tools/log_analyzer.py classroom_log.csv --spark
```

无硬件时也能验证判定逻辑：

```bash
PYTHONPATH=firmware python examples/02_behavior_rules.py
```

烧录与部署见 [`board/deploy.md`](board/deploy.md)，
引脚与外设映射见 [`board/pinmap.md`](board/pinmap.md)。

## 八、数据协议

板端串口输出两类文本行：

```
CBJSON:{"v":"1.2","dev":"TitanBoardMini-RA8P1","t":12345,"count":3,
        "fps":21.6,"raise":1,"down":0,"stand":0,"sit":2,"focus":92,
        "total_raise":5,"total_down":1,"peak":6,"alert":0}

CBEVENT:v=1.2 t=9000 event=RAISE people=1 count=3 focus=92
```

`CBJSON` 为周期状态流（500 ms），`CBEVENT` 为边沿事件流。两者都带 ASCII
前缀，便于用 grep 或文本过滤直接分流，也便于串口助手肉眼阅读。

## 九、隐私设计

- 全部推理在端侧完成，原始画面不上传、不落盘；
- 对外仅输出结构化行为事件，不含任何图像帧；
- 不采集人脸特征、不做身份识别，无法回溯到具体自然人；
- 接入校园系统时通过 `LingXi Behavior Event Schema v1.2` 契约对接，
  传输可进一步加密。

## 十、创新点

1. **端侧闭环**：从采集到语义事件全在 MCU 上完成，无需上位机与云端；
2. **可解释判定**：几何规则替代黑盒分类器，阈值可按教室场景直接调整；
3. **事件引擎**：把逐帧计数压缩为语义事件，输出可直接对接教务系统；
4. **可靠性降级**：SD 卡不可用时自动降级为不落盘，不影响检测主流程；
5. **教学数据沉淀**：CSV 事件日志支持课后回溯与学情分析。
